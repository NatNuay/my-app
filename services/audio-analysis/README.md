# วิเคราะห์เสียงเบื้องหลัง (ทดลอง)

เว็บยังเล่นผ่าน YouTube IFrame เดิม ไม่บันทึกไมโครโฟน ไม่ขอแชร์แท็บ
เมื่อเปิดคลิป เว็บส่งเฉพาะ video ID ไปยังบริการ Python ซึ่งดาวน์โหลดเสียงด้วย
**yt-dlp** แล้วเรียก **All-In-One** เพื่อทำนายเวลา chorus จากเสียงของคลิปนั้น
รวมช่วงเงียบ/เสียงพูดก่อนเพลงโดยไม่เดา offset จากความยาวคลิป
ผลยังเป็นการคาดการณ์ ไม่ได้รับประกันว่าต้น–ท้ายฮุคถูกต้องทุกเพลง

## สถานะการทดสอบ

ผู้ใช้ทดสอบบน WSL/Python 3.11.18 แล้ว: ดึงเสียง RUDE! ออฟฟิเชียลได้
และ All-In-One harmonix-fold0 บน CPU วิเคราะห์จบประมาณ 48 วินาที
คาดการณ์ฮุค 64–80.9, 109–124, 124–138.1, 169–199 วินาที
ระบบรวมสองช่วงติดกันตรง 124 เป็น 109–138.1 โดยไม่เลื่อนเวลาหรือผูกกับเพลงเฉพาะ
ผู้ใช้ระบุจุดเริ่มฮุคแรก 62 วินาที ผลโมเดลจึงยังช้าประมาณ 2 วินาที
ข้อมูลนี้ยืนยันว่าชุดเครื่องมือรันได้บนเครื่องผู้ใช้ ไม่ยืนยันความแม่นยำทุกคลิป

ทดสอบสัญญารับส่งข้อมูล การคัดกรองผล คิว การป้องกันงานซ้ำ และ fallback
รวมทั้งทดสอบ UI ด้วยบริการ/ตัวเล่นจำลอง
cloud นี้ดึงคลิปได้รับ proxy 403 จึงยังไม่ได้ทดสอบเสียงจริงครบวงจรกับหน้าเว็บที่นี่

## ติดตั้งบริการ (แนะนำ Linux หรือ WSL2)

ต้องมี Python 3.11 และ FFmpeg ใน PATH; Node.js ช่วยรองรับการดึงคลิปบางรูปแบบ
ชุดโมเดลนี้มี dependency ที่ติดตั้งยาก โดยเฉพาะ NATTEN / madmom / PyTorch
ทำตามคำแนะนำ upstream สำหรับรุ่นที่เข้ากัน:
https://github.com/mir-aidj/all-in-one#installation

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
# ติดตั้ง PyTorch และ NATTEN ตาม upstream ให้ตรงกับเครื่องก่อน
python -m pip install 'git+https://github.com/CPJKU/madmom'
python -m pip install -r services/audio-analysis/requirements.txt
python -c "import allin1, yt_dlp; print('imports OK')"
python services/audio-analysis/server.py
```

ครั้งแรกโมเดลจะดาวน์โหลดน้ำหนักเพิ่มเติม ต้องอนุญาตเครือข่ายให้แหล่งโมเดลที่ upstream ใช้
และปลายทาง YouTube/ไฟล์เสียง บริการเริ่มได้ไม่ได้แปลว่าดาวน์โหลดโมเดล/คลิปได้
หากติดตั้งโมเดลไม่ได้ ให้ปิด AUDIO_ANALYSIS_URL เพื่อใช้ระบบเดิม

เพิ่มใน `.env.local` แล้วเปิดเว็บด้วย `npm run dev` ในอีก terminal:

```dotenv
AUDIO_ANALYSIS_URL=http://127.0.0.1:8765
```

เปิดคลิปตามปกติ ไม่ต้องกดวิเคราะห์ เว็บถามสถานะทุก 2 วินาที สูงสุดประมาณ 3 นาทีครึ่ง
ขณะรอยังเล่นคลิปและใช้ไฮไลท์เดิมได้
ช่วง chorus ที่ติดกันของโมเดลจะรวมเป็นช่วงเดียว (คลาดขอบไม่เกิน 0.25 วินาที)
ผล chorus จากเสียงจะแทน chorus เดิม ส่วน dance-break จากข้อมูลประกอบจะเก็บไว้ถ้าไม่ทับกัน
โมเดลมีป้าย break/inst/solo แต่ **ไม่แปลงเป็น dance-break อัตโนมัติ**
เพราะไม่ได้ยืนยันว่าเป็นช่วงเบรคแดนซ์จริง

## ขอบเขตบริการ

- Bind เฉพาะ 127.0.0.1:8765; ต้องอยู่เครื่องเดียวกับ Next.js (พอร์ตเปลี่ยนผ่าน AUDIO_ANALYSIS_PORT)
- ถ้าจำเป็นต้องใช้ต่างเครื่อง ให้ตั้ง reverse proxy HTTPS และ AUDIO_ANALYSIS_TOKEN
  ทั้งสองฝั่ง ห้ามเปิด Python port ให้สาธารณะโดยตรง
- อย่าเปิดเว็บที่เรียกงานนี้ต่อสาธารณะโดยไม่มีระบบยืนยันผู้ใช้/จำกัดคำขอระดับ deployment
  คิวจำกัดไม่ใช่ระบบป้องกันการใช้งานผิดวัตถุประสงค์ครบชุด
- ทำงานครั้งละ 1 คลิป รอได้ไม่เกิน 8 งาน; งานที่ไม่มีการถามสถานะนาน 30 วินาทีจะถูกข้าม/หยุด; เก็บสถานะ/เวลาไม่เกิน 128 รายการในหน่วยความจำ
- รับคลิปไม่เกิน 15 นาที ไม่รับ live; จำกัดไฟล์ดาวน์โหลด 100 MB เมื่อ yt-dlp ตรวจขนาดได้
- จำกัดงานละ 3 นาที บนเครื่อง CPU อาจช้าหรือหมดเวลาได้
- เลือก harmonix-fold0 บน CPU เพื่อลดภาระ ไม่ใช่ ensemble 8 โมเดล
- ลบไฟล์ชั่วคราวเมื่อจบหรือยกเลิกงานตามปกติ; การปิดเครื่องฉับพลันอาจเหลือไฟล์ใน temp
- ผลสำเร็จเก็บในดิสก์ 30 วัน (ไม่เกิน 500 คลิป) เปิดเครื่องใหม่ยังใช้ได้
  ผลล้มเหลวเก็บในหน่วยความจำ 5 นาที
- YouTube อาจบล็อกการดึงไฟล์ได้ ไม่มีการข้ามข้อจำกัดเครือข่าย/ล็อกอินอัตโนมัติ
- ใช้กับคลิปที่มีสิทธิ์ดาวน์โหลดและประมวลผล และตรวจเงื่อนไขของแหล่งข้อมูล
- ตรวจใบอนุญาต source/model/dependencies ก่อนเผยแพร่เชิงพาณิชย์:
  madmom แยก license โค้ดกับโมเดล ซึ่งโมเดลระบุ non-commercial

บริการนี้ต้องเป็น process ที่ทำงานต่อเนื่อง ไม่เหมาะกับ Next.js serverless อย่างเดียว
ไม่เปลี่ยนวิธีรับเสียงของตัวเล่น YouTube และไม่มีไฟล์เสียงถูกส่งไปเบราว์เซอร์

## เปิดบนเครื่อง Windows + WSL ที่ติดตั้งเครื่องมือไว้แล้ว

ใน Ubuntu:

```bash
source ~/muverse-audio/.venv/bin/activate
cd /mnt/c/Users/NatNuay/Downloads/my-app-personal
python services/audio-analysis/server.py
```

ถ้าเก็บโปรเจกต์ไว้โฟลเดอร์อื่น ให้เปลี่ยนคำสั่ง cd ให้ตรงที่เก็บ
เปิดหน้าต่างนี้ไว้ จากนั้นเปิดโฟลเดอร์เดียวกันใน VS Code บน Windows
เพิ่ม `AUDIO_ANALYSIS_URL=http://127.0.0.1:8765` ใน `.env.local`
แล้ว `npm ci` และ `npm run dev` (ใช้พอร์ต 3100)
WSL2 รองรับการเชื่อมจาก Windows ไปบริการ Linux ผ่าน localhost ตามค่าปกติ
ทดสอบบริการจาก PowerShell ได้ด้วย:

```powershell
Invoke-RestMethod http://127.0.0.1:8765/health
```

ต้องขึ้น status ok; ค่านี้ยืนยันแค่บริการเปิดอยู่ ไม่ได้ยืนยันว่าโมเดลวิเคราะห์ผ่าน
ถ้าเชื่อมไม่ได้ ให้ตรวจ WSL localhost forwarding ก่อนเปลี่ยน bind ของเซิร์ฟเวอร์

## ลดเวลารอ

- ผลสำเร็จอยู่ที่ `~/.cache/muverse-audio` เปลี่ยนได้ด้วย `AUDIO_ANALYSIS_CACHE`
  เก็บเฉพาะเวลาของท่อน ไม่มีไฟล์เสียงถาวร
- เปิดคลิปเดิมอีกครั้งหรือ restart บริการแล้วอ่านผลเดิมได้ ไม่ดาวน์โหลด/รันโมเดลซ้ำ
- เมื่อเปลี่ยนคลิป frontend หยุดถามสถานะคลิปเก่า บริการหยุดงานนั้นภายในประมาณ 30 วินาที
  ถ้ามีอีกแท็บดูคลิปเดิมอยู่ งานยังทำต่อเพราะยังมีการถามสถานะ
- จำกัด Torch/BLAS 2 threads และปิด multiprocessing ของการเตรียม spectrogram
  เพื่อลดการแย่ง CPU/RAM บน WSL (ต้องวัดเวลาจริงบนเครื่องผู้ใช้ ไม่รับประกันว่าจะเร็วขึ้นทุกเครื่อง)
- ดาวน์โหลดมี deadline 45 วินาที งานรวม 180 วินาที ไม่รอค้าง 10 นาที
  การหมดเวลาไม่ได้ทำให้วิเคราะห์เสร็จ; จะแจ้งและกลับไปใช้ข้อมูลระบบเดิม
- สถานะหน้าเว็บแยก รอคิว / เตรียมเสียง / วิเคราะห์เสียง / หมดเวลา
- terminal ของบริการแสดงเวลาที่แต่ละงานใช้เมื่อสำเร็จหรือล้มเหลว
- คลิปใหม่ยังต้องประมวลผลด้วย CPU ไม่ใช่การวิเคราะห์ทันที
  ยังไม่ได้ benchmark เสียงจริงบนเครื่องผู้ใช้ด้วยการตั้งค่าใหม่นี้
